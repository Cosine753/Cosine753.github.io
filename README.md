# 个人学术主页

面向 PhD 申请与研究介绍的单页学术主页，外加一份同源的 CV。
纯静态、零外部依赖——无 CDN、无 Google Fonts、无跟踪脚本，中国大陆网络环境下可完整加载。

## 快速上手

```bash
powershell -ExecutionPolicy Bypass -File fill.ps1
```

三步：

1. 用编辑器打开 **`myinfo.txt`**，把个人信息字段填上（选填的可以留空）
2. 跑 `fill.ps1` —— `index.html` 和 `cv.html` 里的个人信息占位符会一次性替换掉
3. 预览并导出 `cv.pdf`，确认无误后跑 `fill.ps1 -GoLive`，再用 `check.ps1` 做发布前自检

不建议手工去改 HTML。除了替换占位符，`fill.ps1` 还顺手做了几件容易漏的事：

- 选填项留空时，把页面上对应的整块删掉，不留空标题、空行和已经失效的说明注释
- ORCID 填了就自动取消注释启用，留空就把那两行整个删掉
- 重新生成带姓名的 `og.png`，并刷新 `sitemap.xml` 的 `lastmod`、主页与 CV 页脚的更新月份

动手前每个被改的文件都会存一份 `.bak`。需要回退时，优先用对应的 `.bak` 恢复单个文件；
若用 Git，请先看 `git diff`，再只恢复确认过的目标文件，避免覆盖仓库里其他尚未提交的修改。

## 一、你需要填写的内容

全部在 `myinfo.txt` 里，文件内每个字段上方都有说明。这里只讲两个容易出错的：

**`姓名英文拼写`** —— 必须与你护照、成绩单、已发表论文的署名**完全一致**。
`Zhang Wei` / `Wei Zhang` / `Zhang, Wei` 选你论文上用的那一种，然后一直用它。
拼法不统一，你的成果就没法被归到同一个人名下。

**`邮箱`** —— 优先用机构邮箱。页面上只留一个 QQ/163/Gmail，读者会觉得你没有单位归属。
填了公共邮箱 `fill.ps1` 会提醒一次，但不拦你。

选填项（`学位二`、`临床或工作经历`、`ORCID`）留空就好，对应内容会被整块删掉。

**ORCID 建议去注册**（<https://orcid.org>，免费，五分钟）。它是唯一能把你和重名者永久
区分开的持久标识符，换单位、换邮箱都不受影响。填进 `myinfo.txt` 就会自动在主页和 CV 上启用。

> `myinfo.txt` 里给的 ORCID 示例 `0000-0002-1825-0097` 是一个真实存在的演示账号。
> 照抄上去等于把别人的持久标识符写成自己的，`check.ps1` 的 D 项会拦住这种情况。

### 填完之后

`fill.ps1` 跑完会把剩下的步骤列出来。核心是这一条：

预览首页、导出 `cv.pdf` 并确认无误后，运行：

```bash
powershell -ExecutionPolicy Bypass -File fill.ps1 -GoLive
```

这会删除 `index.html` 的 `noindex` 并刷新 sitemap 日期。`noindex` 还在的时候，
搜索引擎不会收录这个页面，导师搜你的名字找不到你。若你已经完全确认内容，
也可以第一次填充时直接运行 `fill.ps1 -Yes -GoLive`。

## 二、发布前自检

```bash
powershell -ExecutionPolicy Bypass -File check.ps1
```

任何**阻断项**不过就返回非零退出码，提醒你先别推。七项检查：

| | 查什么 | 为什么 |
|---|---|---|
| **A** | 还有没有占位符没换掉 | 逐个列出文件名和行号 |
| **B** | 收录开关与填写状态是否一致 | 没填完却删了 `noindex`（半成品被收录），或填完了却忘了删（导师搜不到） |
| **C** | 有没有混进 CDN、外部字体、外部图片 | 你在中国大陆，这类资源会让页面卡住或白屏 |
| **D** | 虚构 / 示例内容有没有出现在页面上 | 包括初版占位样例，以及上面那个示例 ORCID |
| **E** | 页内导航指向的锚点是否真的存在 | 反过来也查：有版块却没进导航 |
| **F** | 页面引用的本地文件是否真的在仓库里 | `cv.pdf`、`og.png` 缺了线上就是 404 |
| **G** | `index.html` 与 `cv.html` 的姓名、邮箱是否一致 | 填完之后两个文件各自独立，改一个容易忘另一个 |

关于注释的处理原则：**A、E、F 问的是「页面上实际会呈现什么」**，注释里的内容不算数；
**C、D 问的是「文件里躺着什么」**，注释里出现同样要提醒——一段被注释掉的 CDN 引用，
哪天被人取消注释就会立刻生效。

脚本是 UTF-8 **带 BOM** 保存的。Windows PowerShell 5.1 读不带 BOM 的中文 `.ps1`
会按 GBK 解码、报莫名其妙的引号错误——如果你要改这些脚本，保存时记得保留 BOM。
`myinfo.txt` 同理，用记事本另存时「编码」要选 UTF-8（存错了 `fill.ps1` 会拦住你）。

## 三、导出 CV

`cv.html` 是排版源文件，不是成品。填完之后：

1. 浏览器打开 `cv.html`（屏幕上会有一段黄色说明，打印时自动隐藏）
2. `Ctrl+P`
3. 目标选「**另存为 PDF**」，纸张 **A4**，边距「默认」，缩放 **100%**，
   并**关掉「页眉和页脚」**——否则纸上会印出浏览器加的网址和日期
4. 存到仓库根目录，文件名固定为 **`cv.pdf`**
5. 回到 `index.html`，取消 CV 链接那行的注释，把日期改成当月

文件名固定用 `cv.pdf`，旧邮件里的链接才能一直有效。**不要放网盘链接**——权限墙会把
海外和大陆读者分别挡在外面。

`cv.html` 末尾有一段注释掉的「研究工作」，默认与主页保持一致（不展示）。
注意 **`cv.pdf` 放在仓库根目录，任何人都能下载，公开程度和主页相同**。
如果你要做的是发给特定单位的非公开版 CV，启用那一段是合适的——未投稿稿件在 CV 里
按「稿件准备中」列出是常规做法——但那一版请另存为 `cv-full.pdf` 并且**不要提交进仓库**
（`.gitignore` 里已经替你挡了这个文件名）。

## 四、社交卡片图

`og.png` 是导师把链接贴进邮件或微信时显示的预览图。`fill.ps1` 会自动重新生成，
也可以单独跑：

```bash
powershell -ExecutionPolicy Bypass -File tools\make-og.ps1
```

不传参数时它自己去 `index.html` 里读姓名。想改配色或文案就直接改这个脚本。
只用了 .NET 自带的 `System.Drawing`，没有第三方依赖。

## 五、更新与发布

```bash
git add . && git commit -m "更新" && git push
```

推送后约一分钟自动重新发布。

**验证时务必带上随机查询串**，例如 `https://cosine753.github.io/?v=123`。

## 六、暂未展示的版块

`index.html` 里有三段被注释掉的版块，`cv.html` 里有对应的两段。都写好了，等你有内容时启用。

| 版块 | 位置 | 说明 |
|---|---|---|
| **论文** `#publications` | index.html + cv.html | 给了一条示例条目结构。加第二条就把整个 `<li>` 复制一份，字段名改成「论文二…」 |
| **科研项目** `#projects` | index.html + cv.html | 同上 |
| **研究工作** `#works` | index.html + cv.html | 四条未投稿稿件，已写好正文 |

启用任何一段都是**两件事，必须同时做**：删掉该段前后的注释标记，**并且**在页内导航
`.site-nav` 里把对应的 `<li>` 取消注释。漏一边 `check.ps1` 的 E 项就会报——
少了导航是提醒，导航指向不存在的版块是阻断。

样式（`.pub`）已经写在 `<style>` 里了，启用时不必回来补 CSS。

### 关于占位符

论文和科研项目的模板里也用了 `{{需你填写:...}}`，但它们躺在注释里：

- **没启用时**：`check.ps1` 报「注释里有 N 处占位符，不算问题」，`fill.ps1` 也会跳过，
  不会逼你在 `myinfo.txt` 里给值——论文条数不固定，本来就不适合塞进 `键 = 值` 的格式
- **一启用**：它们立刻变成阻断项，逼你上线前填干净。不会出现「论文一标题」这种模板文字
  被推上线的情况

所以这两块是手工填的，填完直接跑 `check.ps1` 验收。

### 两条不要越过的线

**状态要写实。** 已发表就写期刊和年份；在审就写「在审」；还没投就写「稿件准备中」。
把在投写成已发表，评审委员会核一下就穿——这是学术诚信问题，不是措辞问题。

**未投稿论文不要放头条结论。** 写研究问题、方法和你做到什么程度是安全的，把主估计值
公开则可能影响后续投稿。真正打动评审的本来也不是结论，而是过程——核验规模、可复现设施、
以及你推翻自己结论时的处理方式。

科研项目那一栏，写清楚**你实际承担的具体工作**（数据清洗、统计分析、影像采集质控、
伦理送审……），不要只写「参与」。只是挂名或旁听的不要列——面试时被追问细节答不上来，
比少列一条项目的代价大得多。

（原本一起注释掉的「公开工具」版块已经启用，就是主页上的 `#tools`。）
